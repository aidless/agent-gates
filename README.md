# agent-gates

三个把"方法论"变成"有退出码的闸"的小工具。纯 Python 标准库，无依赖。
每个闸都自带 `--selftest`，而 selftest 里有一半断言是**反证**：注入违规必须变红。
一个只能变绿、不能变红的检查是装饰品，不是闸。

来源：这套东西是在一个 AI agent 工作区里被自己的事故逼出来的。三次事故、两次闸自己判错，
教训都留在下面第 3、4 节，没有擦掉。

```
config.py              # 本机布局集中在这里（路径，不是判据）
ledger_append.py       # 闸一：教训台账的回执行门
eval_gate.py           # 闸二：评测涨分的假阳维度
retrieval_probes.py    # 闸三：检索能力三探针
examples/              # 假数据，让三个 selftest 在干净目录里跑通
```

## 快速开始

```bash
# 三个 selftest（不用 examples 数据的那两个）
python3 ledger_append.py --selftest
python3 retrieval_probes.py --selftest

# eval_gate 的 selftest 要一份能构造夹具的基线
python3 eval_gate.py --selftest --baseline examples/runs/baseline.jsonl \
                               --itemset examples/itemset.jsonl

# 用 examples 看闸怎么判：散弹作答涨的那 1 题会被扣回去
python3 eval_gate.py --baseline examples/runs/baseline.jsonl \
                     --current examples/runs/current-spray.jsonl \
                     --itemset examples/itemset.jsonl
# → GREEN | 基线 PASS 5 → 当前 6 (Δ+1) | 有效涨分 +0（已扣掉 1 题可疑通过）| 可疑通过: t5

# 退化版必须红
python3 eval_gate.py --baseline examples/runs/baseline.jsonl \
                     --current examples/runs/current-regressed.jsonl \
                     --itemset examples/itemset.jsonl
# → RED | Δ-3 | rc=1

# 检索探针配示例语料
python3 retrieval_probes.py --root examples --probes examples/probes.json --min-chunks 6
```

`examples/` 里的读数只证明**机制能跑**，不证明检索质量——那点语料太小。

## 1. 三个闸各自解决什么问题

### 闸一 `ledger_append.py` —— 教训台账的回执行门

问题：教训记下来了，但没人能证明它当时是真的。半年后你看到"某命令会毁档"，
既不知道该信到什么程度，也没法知道它是否还成立。

做法：往台账追加一条时，强制带一条**可复现的验证命令**。命令在锁外跑（持锁跑长命令
会卡住别的会话），`rc != 0` 就**拒绝写入**——不接受一条自己都证不了的教训。通过则把
`- **回执** \`cmd\` → rc=0 @ UTC；输出摘要：…` 写进条目，之后可以 `parse_receipt()` 取回。

关键点：这里刻意用 **rc 当判据，不用输出**。零输出的命令（`true`）仍然算通过，
否则"静默正确"的验证会被误杀。

设计取舍：事后无法反演。一条已经落盘的教训，如果当时没记命令，事后补不出来
（原始 transcript 可能已经不在了）。所以这道门只能建在**写入路径**上，改历史没有意义。

### 闸二 `eval_gate.py` —— 评测涨分的假阳维度

问题：几乎所有 eval 对比只测"该过的过了吗"，不测"不该过的过没被放过"。
于是一个把关键词整篇念一遍的散弹答案，也能让分数涨上去。

做法：拿题集的 `expect` 关键词，检查答案里**至少有一对相邻关键词的距离 ≤ 120 字符**。
满足就是"散弹蒙对"，从涨分里扣掉，输出的是 `有效涨分`（effective_delta）而不是裸 Δ。

关键点：判据的方向必须是"**有一对紧邻**"，不是"整体跨度小"。
后者量的是"答案多长"，会把长而详细的好答案判成可疑——这正是第 3 节那次翻车。

### 闸三 `retrieval_probes.py` —— 检索能力三探针

问题：记忆/笔记/台账里有几万块文本，你怎么知道"检索还行"是真的还行？
凭感觉不行，凭"我搜了几个词都能搜到"也不行——那只是同义词碰巧撞上了。

做法：纯 stdlib BM25，三组探针，每组都要**红/绿两段**（能过也要能挂）：

- **同义**：同一件事换个说法，top-k 必须有交集。
- **否定**：`"X 要不要做"` 与 `"X 怎么做"` 的 top-1 必须**换块**，
  而且问"要不要"时 top-1 得是讲"不要"的那块。判的是顺序，不是集合——
  只换了排序、集合没变，恰恰是否定被正确理解的形态。
- **多义**：同一个词的两个义项，top-1 必须落在不同块。

判据是 rc：新失败 exit 1，已登记的 `known_fail` 不阻断。

关键点：**必须剔除记录判据本身的那些块**。写下"检索探针应该 X"这条记录之后，
探针就会在它自己身上测到自己，分数从 5/7 变成 7/7——那不是修好了，是自我实现。
`SELF_MARKERS` 就是干这个的，`--include-self` 能复现那种假绿。

## 2. 设计原则：判据不进 config

`config.py` 只放**路径**（`MEMORY.md` 在哪、台账在哪、题集在哪、探针集在哪），
全部可用 `AGENT_GATES_*` 环境变量或命令行覆盖。

阈值和判据（`FP_WINDOW = 120`、`SYN_K`、红黄线）**留在各自脚本里**。
理由：路径是本机事实，换个项目就该换；判据是一个可辩的主张，跟着代码走才能被 review、
被 `--selftest` 钉住。把判据挪进 config，等于给"悄悄调松阈值让闸变绿"开了个后门。

同理，探针集和题集是**项目内容**，不是脚本内容——它们必须是"你这个语料里真实存在的问题"，
所以整份外置成 `probes.json` / `itemset.jsonl`，脚本里一行不留。

## 3. 翻车记录一：`max-min` 把好答案判成了蒙对

假阳判据的第一版是"关键词整体跨度 > 120 就是散弹"。

真数据一跑就翻车：一道题被标红，涨分从 +5 扣成 +4。核查后发现那是一份**长而详细的好答案**
（3692 字符，引用 `ops/upgrade.sh:55-80` 逐项列出 6 个备份对象），第 4 个关键词出现在
2642 字符处——跨度当然大。它只是答得长。

`max-min` 量的是"答案有多长"，不是"有没有蒙"。数据看得再仔细也没用，判据本身取错了底物。
改成"至少有一对相邻关键词间距 ≤ 窗口"之后恢复 +5，并且给这个形态加了断言：
`selftest` 里那份"长答案有一对共现"必须判**不可疑**，谁把判据退回 `max-min` 谁就红。

这类错误的通名是**让"大"盖住"对"**。同一个病还有另外两张脸，写在这里备查：
①**语料源错**——判"声明"的闸读了"实现"；②**把测量结果当判据**——判据要
"阈值 + 指标名 + 要求语气"三样齐全，缺一样就不算。

## 4. 翻车记录二：闸在自己的产物上把自己测绿了

检索探针上线的当天，真实语料跑出 **5/7**，两条失败被具名登记为 `known_fail`。

然后我把这两条教训写进了记忆文件和台账。再跑——**7/7**。

看起来像修好了。实际是：那两条失败的探针，问的正是"台账怎么追加 / 台账不要怎么写"，
而我刚刚写下的记录里全是这些词。探针在自己的产物上测到了自己，分数当然满分。
把那两块剔除，立刻回到 5/7。差的 2 条不是修复，是自我实现。

修法是 `SELF_MARKERS` 按**内容特征**剔除记录判据的块（不能按块序号，序号会漂），
并且保留 `--include-self` 让人能亲手复现那个 7/7。

引申出来的通则，一句话：**判据的输入不许混进判据自己的产物**。
同样的形状还有两例，都在这个仓库里：B3 那次是"用长度当正确性"，
`SELF_MARKERS` 词表本身也是漏的（新写的记录里不一定含登记词）。

## 5. 已知漏处（不打算假装没有）

| 漏处 | 现状 |
|---|---|
| 否定探针在微型语料下有天花板 | 示例数据里就是失败的，登记为 `known_fail`。纯词频模型在语料小时没有区分度；换成语义检索后应自己变绿，届时把 `known_fail` 那行删掉让它重新成为阻断项。 |
| 真实语料 5/7 是 BM25 上限 | 不是语料没写好，是词袋模型换说法就召回不到。换向量检索才有机会。 |
| `SELF_MARKERS` 是白名单 | 新写的记录若不含任何登记词就会漏网。它只是让读数不变绿，不是完整解。 |
| 闸一只保证"当时能复现" | 台账条目里的命令半年后可能因为环境变化跑不了。回执自带时间戳，但没有过期机制。 |
| `eval_gate` 只判关键词共现 | 措辞不同但语义正确的答案仍可能被判 FAIL。它防的是假阳（蒙对），不解决假阴。 |

## 6. 接到自己的项目上

1. 改 `config.py` 的默认路径，或全部用环境变量：`AGENT_GATES_MEMORY`、`AGENT_GATES_NOTES`、
   `AGENT_GATES_LEDGER`、`AGENT_GATES_ITEMSET`、`AGENT_GATES_BASELINE`、`AGENT_GATES_PROBES`。
2. 写自己的 `itemset.jsonl`（字段 `id/cat/q/expect/src/hint/note`）。
   一份 `runs/*.jsonl` 基线（字段至少含 `id/pass/answer/q/seconds/exit`）——
   `expect` 不存进 runs，只存题集，因为它是题集属性不是运行产物。
3. 写自己的 `probes.json`：同义/否定/多义各挑**真实让你搜不到**的那几对，
   不要造题。第一批跑出来必然有几条不过，先登记 `known_fail`、把能过的锁住，
   然后去改检索，而不是去改探针。
4. 台账格式：`## L-<系列>-<号> <标题>` 加六字段（情境/动作/结果/证据/置信度/状态）。
   `ledger_append.py --verify-cmd '<一条真的能跑的命令>'`。
